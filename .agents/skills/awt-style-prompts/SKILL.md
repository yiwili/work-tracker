---
name: awt-style-prompts
description: Import historical work-item title examples and maintain AI Work Tracker's work-filter, task-writer and time-estimator prompts. Use for this project's title style and role configuration, not for importing old tasks as new work.
---

Use `GET /api/agents` to inspect five effective role prompts: scope_filter, task_writer, time_estimator, manual_writer and style_template. Defaults are in `awt/prompts/`. User supplements live in `Settings.agent_prompts`. Preserve unrelated settings when calling `PUT /api/settings`. `Settings.style_template` is applied to business work-item and quick manual-item naming.

For an explicitly supplied JSON/CSV/XLSX/XLS reference, call `POST /api/style/import` with `{"path":"absolute local path","since":"YYYY-MM-DD","include_git":true}`. Alternatively upload `filename` plus `content_base64` instead of path (20MB limit). All valid records are saved in SQLite history, deduplicated by external ID/project or title/date/project. The requested threshold selects style examples; initial reference starts on 2026-09-15. The first import generates a reusable style template when AI is enabled. Subsequent imports preserve that template; explicit `POST /api/style/generate` regenerates it. Inspect `GET /api/history?offset=0&limit=20`. History is never imported as today's tasks, and comments/operation logs are not sent to the model.

Gitee integration reads V5 Issues for the authenticated user's assigned/created/all scope, with optional repository restriction. Save a user-supplied token through `POST /api/gitee/token` (api_key field), config through `PUT /api/gitee/config`, inspect `/api/gitee/status`, and manually fetch through `POST /api/gitee/sync`. Enabled config schedules periodic imports only while the local service runs. Tokens are encrypted locally or read from GITEE_ACCESS_TOKEN. Never infer or reuse unrelated credentials. Never write to Gitee. Failed or incomplete fetches leave historical rows unchanged.

User-authorized enterprise publishing is a separate workflow in `gitee_enterprise.py`, using its own Token or GITEE_ENTERPRISE_TOKEN. Configure `Settings.gitee_enterprise` via `/api/gitee/enterprise/config`. Pre-set rules map an exact title, title keyword or project prefix to an enterprise program ID; exact > contains > prefix, then longest match. Ambiguous matches require user selection. Fetch enterprise/project/type lists through the corresponding enterprise endpoints; never substitute a repository ID for a program ID. `/api/gitee/enterprise/preview` saves exact outbound content. Only an explicit request or user click confirming that concrete preview authorizes `/api/gitee/enterprise/publish` with confirmed=true. Preserve known created links, never auto-retry uncertain writes, and never send raw logs. Minutes go to estimated duration, not registered actual work. The V5 read-only restriction above applies to historical collection, not explicitly confirmed enterprise publishing.

Inspect the imported examples and metadata in settings. Prefer concise action + business module + visible issue/feature. Example: “修复附件管理全文提取不到的问题”; keep “达梦大字段类型转换错误” as a technical explanation in details. Merge troubleshooting, changes and verification for the same business objective. Keep genuinely separate features/issues distinguishable. Do not invent completed work or inflate task counts to satisfy a reporting goal.

Keep work-item naming distinct from Git commit conventions: a single project tag such as 【上海工程】 may remain, followed by plain action words 修复、新增、优化、完善. Do not add a second bracketed action/type tag. For example, use 【上海工程】修复卷内目录打印问题. Imported Git titles remain raw references, but their double-tag formatting must not be copied into work-item templates or generated titles.

After an authorized prompt/style change, use a representative mocked test and, if warranted and authorized, one real configured-model analysis. Existing reviewed entries must survive. Validate work-relevance exclusion, evidence references and exact-minute behavior through application tests rather than merely checking prompt wording. Do not change model credentials or CCSwitch configuration as part of style editing.
