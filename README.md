# Work Tracker（拾时）

本地优先的 AI 工作记录与每日工时管理工具。读取 Claude Code / Codex 本地 JSONL 历史及 Git 提交，先统计每日会话和消息，再由 AI 按实际工作目标归纳全天任务；补录沟通、运维等事项，审核确认工时并导出 Markdown。支持历史工作项风格学习、DeepSeek / GLM / CCSwitch，以及可选的 Gitee 企业版工作项创建。新安装默认关闭云端模型与自动抓取，远端创建必须先核对提交预览。

## 启动

需要 Python 3.12+、Node.js 20.19+、Git。Windows 双击 `start.cmd`，或运行：

```powershell
.\start.ps1 -Setup
```

首次安装依赖并构建界面；以后直接运行 `start.cmd`。访问 <http://127.0.0.1:8765>。服务仅监听本机。停止运行可按 Ctrl+C。

手动启动：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
cd frontend
npm ci
npm run build
cd ..
.\.venv\Scripts\python.exe -m awt.cli serve
```

开发时后端同上，前端在 `frontend` 运行 `npm run dev`，访问 <http://127.0.0.1:5173>，由 Vite 代理 API。接口文档：<http://127.0.0.1:8765/docs>。

## 使用

1. 设置页检查采集路径。默认读取 `~/.claude/projects`、`~/.codex/sessions` 和 `~/.codex/archived_sessions`；可填写多个目录或指定 JSONL 文件。添加明确的 Git 仓库根目录和目录到项目名称映射。先配置敏感目录排除规则。
2. 选择日期，点击“采集全天对话”。先查看会话数、用户消息和 AI 回复数，展开会话可查看来源。默认仅选择 Codex 分析；可添加 Claude Code，Git 提交仅作为可选辅助证据，不按条生成工作任务。首次会将可读历史归入本地事件库，按设置时区加载指定日期，以后增量入库。不会修改源日志、仓库或提交。
3. 在设置中选择 DeepSeek、GLM 或 CCSwitch，保存并测试连接，再开启模型分析。点击“AI 分析全天对话”，同一目标的追问、修改、测试按实际工作归并；大记录分段整理后再统一合并。AI 未接通时只统计会话，仍可人工录入，不会按每条提问拆任务。
4. 点击任务标题编辑内容、日期、项目、分类、完成状态及确认分钟数。候选建议是低置信度观察值，不代表人的精确工作时长。缺少依据时显示“待估算”，默认确认工时为零。
5. 补录实际沟通、会议等活动；可选填开始结束时间以检测重叠。勾选任务可合并，右侧可拆分、删除或查看证据。合并保留人工确认分钟数，需自行核对重复投入。拆分必须守恒原确认分钟数，并继承证据以供人工复核。
6. 默认合计恰好 480 分钟才能确认，479/481 均会被服务端拒绝。可以导出未完成草稿，导出内容会标明状态。已确认日报在任务修改、删除、合并、拆分或重新生成后恢复待审核；修改时区或目标也会撤销确认。
7. 时间线可按来源、项目、任务和内容筛选，查看时间、脱敏摘要与原始文件字节偏移引用。

## 业务标题、专用角色和工时分配

- 默认先运行“工作相关性筛选”，再做全天业务目标归并。私人、与项目无关和无法判断的提问不提供自动任务或工作时长依据；即使发生在项目目录中也不自动算工作。页面保留采集总量，另显示工作、排除和待判断数量。
- 仅了解现有系统、请AI梳理源码/功能区别/适用场景，默认不生成工作项或工时；阅读源码、长篇回复和工具耗时不代表实际实施。学习例外要求同一主题可观察活跃讨论严格超过60分钟，首尾跨度、长时间等待及不同主题不能凑时长；实际开发、修复中的理解环节合并到业务目标，不单列学习项。此规则用于后续分析，保留已审核和人工固定记录。
- 标题采用“动作 + 业务模块 + 用户可见的问题/功能”；把排查、改动和验证归入同一工作目标。数据库类型、异常类和代码实现放入详细内容。例如“修复附件管理全文提取不到的问题”。
- 设置页支持 JSON、CSV、XLSX、XLS 文件上传或本机路径导入。历史记录去重保存在 SQLite，日期筛选决定哪些标题用于风格参考，最多保留80条范例，含可选 Git 提交标题。首次导入可由 AI 生成可编辑的命名风格模板，之后保留已有模板，需主动点击才重新生成。不把历史事项当作当天工作，不发送原始评论、附件或操作日志。
- 工作项可保留单个项目标签，如“【项目名称】修复附件提取问题”；修复、新增、优化等动词不加第二组方括号，避免照搬 Git 的双标签规范。
- 设置页展示五个角色的默认提示词及可编辑补充偏好：`scope_filter`、`task_writer`、`time_estimator`、`manual_writer`、`style_template`。默认文件在 `awt/prompts/`，证据和分钟校验由程序强制执行。
- 项目技能在 `.agents/skills/`，由根 `AGENTS.md` 指引：`awt-daily-worklog`、`awt-time-allocation`、`awt-style-prompts`。它们通过本地 API/CLI 操作，不访问密钥存储或直接写数据库。
- 手动录入时间后默认固定，编辑窗可勾选或解除“固定此项工时”。主动点击“AI 估算并分配 8h”后，保留固定项，让模型按难度、范围和可观察活动独立估算，再按权重将剩余目标分钟精确分配给已有合格工作项。例如固定客户沟通1h，只分配剩余7h。目标也可在设置中调整。
- 工时弹窗支持添加多个人工事项，仅需选择运维/沟通、填写简称与时长；AI 参考历史风格命名并保留其固定时长。失败后保留输入草稿，重试使用同一请求编号防止重复建项。
- AI 分配值与独立估算值均使用30分钟（0.5h）单位，例如1h、1.5h、2h。人工固定时长不被静默取整；若剩余目标不是30分钟的整数倍，提示用户调整后再分配。编辑器的增减步长不改变此规则。
- AI 填写的是工时分配草稿，不是实测工时；页面与导出标明来源和理由，不自动确认日报。模型的独立估算与目标分配差别过大时会提示。没有真实合格工作、所有项已固定且仍不足、或固定时间超额时拒绝自动补足，不新增虚构事项。
- 时间参考区分“会话跨度”“可观察活跃片段”“工具返回运行时长”。日志有消息时间，无法还原用户离开电脑、思考和客户沟通的准确时长。活跃片段只累计相邻事件不超过默认5分钟阈值的区间，原时间线中的私人事件会截断工作区间；并行活动取并集。它只影响估算参考，不自动折算人的实际工时。
- AI请求在数据库写事务外等待；结果落库前重新检查任务、固定分钟和对话范围，期间的人工修改会保留并拒绝过期结果。同一天的分析和估算互斥，避免重复请求。
- GLM-5.3 的思考与最终结果共享输出预算。全天筛选和业务归并为该模型使用轻度思考、流式接收并预留至少32768 tokens（包括通过CCSwitch读取的模型），连接测试仍只用64 tokens；上限不代表固定消耗。仅完整结束后解析最终文本，思考内容不写入工作项。不自动重复付费请求，截断或流中断时保留原任务，并在页面及日志说明失败阶段和输出预算。

相关 API：`GET /api/agents`、`POST /api/style/import`、`POST /api/reports/{date}/estimate-time`。CLI 增加 `awt conversations --date ...` 和 `awt estimate --date ...`。

## Gitee 历史抓取与企业工作项创建

- 普通 Gitee V5 接口用于抓取本人负责/创建的历史 Issues，可限定仓库，支持分页与去重。启用定时抓取后，仅在本地服务运行时执行。配置本机加密 Token 或服务端环境变量 `GITEE_ACCESS_TOKEN`。
- 企业版使用独立凭据：点击左侧“企业工作项”，即可配置 Token、读取企业和项目、预设标题映射并预览推送；偏好设置中也保留配置入口。没有当天工作项时仍可进入配置页。也可使用服务端环境变量 `GITEE_ENTERPRISE_TOKEN`；不会自动复用普通仓库凭据。
- 可预设项目前缀、标题关键词、完整标题到企业项目的映射；完整标题优先，其次关键词，再次项目前缀，同级按更长的规则匹配。支持从历史标题快捷添加常用前缀。无明确规则时只接受唯一项目匹配，重名或无法匹配时手动选择。
- 日报选择工作项后点击“提交到 Gitee”，核对项目、工作项类型和发送内容，再明确确认创建。发送标题、可选详情、工作日期和预估工时，不上传原始对话或证据日志；不自动关闭任务，也不登记实际工时。
- 本机保存创建记录，重复提交跳过已创建项；部分失败可重试。结果未知的网络中断不会自动重发，可输入远端工作项数字 ID 核对并关联。预览后修改任务、工时、企业配置或凭据，需要重新预览。
- 企业工作流若有额外必填字段，远端校验可能拒绝创建，页面会保留失败状态，需核对项目要求。企业接口的真实访问与写入权限由所配置账号决定。

## 数据与隐私

- SQLite 数据库默认位于 `data/work.db`，可通过 `AWT_DATA_DIR` 指定其他目录。迁移在启动/CLI 运行时自动执行。所有事件以 UTC 存储，工时以整数分钟存储。
- Git 仓库只保存代码、依赖与项目说明。数据库、凭据、个人日志、环境配置、依赖目录和测试产物均被忽略；不要将真实数据或 Token 添加到提交中。
- 备份时先停服务，再复制整个数据目录（含 SQLite WAL 文件，如有）。测试使用独立临时数据库。
- 日志不复制原文文件；事件库仅存脱敏、长度受限的摘要和本机原始引用。默认规则覆盖常见 Token、密码、Bearer、私钥和 URL 凭据。自定义正则用于额外敏感数据。自动脱敏不是覆盖所有秘密的保证；敏感项目请先排除。
- 目录排除和脱敏变更作用于后续采集/分析，不会自动擦除已有入库记录。需要重新采集时可在停机并备份后使用新数据目录，源日志保持原状。
- 新安装默认关闭模型分析。显式开启后，发送所选日期脱敏后的用户消息、AI 回复以及合并后的工具类型、次数和本地验证状态。不发送原始工具输出、原始文件引用、工作目录或服务端环境变量。分析使用已采集的长度受限摘要；不能恢复源日志缺失内容。模型失败、引用无效或输出截断时保留原有草稿，不回退到逐条提问拆任务。
- DeepSeek / GLM：设置中预填官方完整 API 地址和模型名，可按账户实际可用模型修改。输入 API Key 后保存；Windows 上用 DPAPI 加密保存到数据目录的 `model-credentials.json`，不写入 SQLite、不在 GET 接口中回显。也可通过设置中的服务端环境变量提供密钥；非 Windows 当前需使用环境变量。密钥绑定供应商和接口地址，切换地址不会把原密钥发到新地址。
- “保存并测试连接”在按钮旁显示处理中、成功或具体失败原因，期间禁用设置输入和重复提交；已保存但连接失败会明确区分，无效字段或项目映射导致未开始测试也会提示。连接测试失败后可直接重试，无需重新输入已成功保存的密钥。
- CCSwitch：只读复用它写入的 Claude Code `settings.json`，检测 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY` 和模型，使用 Anthropic Messages 接口。支持直连供应商和本地代理，按每次请求读取当前配置，不修改 CCSwitch 数据库或配置文件。可指定配置文件路径、可覆盖模型。官方登录 OAuth/订阅凭据不自动复用。仅检测配置不代表调用成功；“保存并测试连接”会发送简短真实模型请求，可能消耗少量额度，不发送工作对话。
- 重新分析成功后，事务内替换未编辑且确认分钟为零的自动草稿（包括旧版逐条规则草稿），保留人工事项、人工编辑、已填工时以及删除决定。对话原始事件不删除。
- Git 采集保存提交的作者/提交时间、文件与增删行摘要。未提交文件状态单独记录“当前观察时间”，不会伪装成历史修改事件；提交不等于测试通过。

## CLI

### 交互式终端版

Windows 双击 `start-terminal.cmd`，或运行：

```powershell
.\start-terminal.ps1 -Setup
# 指定工作日期或端口
.\start-terminal.ps1 -Date 2026-10-24 -Port 8765
```

终端版只安装 Python 依赖，无需 Node.js、前端构建或浏览器。复用已运行的本机服务；未运行时会启动自己的后台，退出时仅关闭它自己启动的后台，不停止原有网页服务。

也可直接运行：

```powershell
.\.venv\Scripts\python.exe -m awt.cli terminal --date 2026-10-24
# 只连接现有服务，不自动启动
.\.venv\Scripts\python.exe -m awt.cli terminal --no-start
```

菜单包含当日对话统计、日志采集、AI 业务归纳、多个人工事项、半小时工时分配、工作项编辑/删除、日报确认与 Markdown 导出、模型/来源配置、历史风格导入、企业项目/标题映射，以及 Gitee 企业工作项预览提交。API Key 和 Token 使用隐藏输入，不在输出中回显。AI 分配保持草稿，日报确认仍需用户明确核对。

企业推送会逐项展示目标项目、类型、描述和预估工时，并在最后要求明确确认；取消不会发出创建请求。终端版不向任何 Gitee 代码仓库执行 Git 提交或推送。

### 命令行子命令

激活虚拟环境后使用 `awt`，或将其替换为 `.venv\Scripts\python.exe -m awt.cli`：

```text
awt doctor
awt collect --date 2026-10-24
awt analyze --date 2026-10-24
awt report --date 2026-10-24 --format markdown
awt serve --port 8765
```

## 实现边界

任务分析以全天对话为上下文，让模型按实际目标进行跨会话归并；证据引用必须来自当日所选来源，完成状态由本地行为证据判定，不接受模型凭空写出的已验证状态。用户最终审核工时，系统不根据会话跨度或对话条数自动填报。项目归属优先采用记录的 cwd、工具显式 workdir、文件绝对路径、Git 根目录和目录映射。同一会话 cwd 切换、显式跨目录工具执行和补丁跨仓库时会拆分归属；尚未对 shell 文本中的所有 `cd`、嵌套脚本或任意跨目录文件访问做语义推断，未记录 cwd 的活动需人工核对。已审核任务重新分析时保留修改，已删除自动任务保留删除决定。

采集器兼容常见 Claude Code / Codex JSONL 的已知结构、跳过未知记录及损坏行；厂商未来格式需追加适配。跨文件复制依靠来源、会话、UTC 时间、事件类型和脱敏内容构建稳定去重键。完整行才推进检查点，尾行稍后重试；文件截断/替换会重读并去重。

后续可扩展 Cursor 等适配器、统计视图和 `WorklogExporter`；目前为本机单用户工具，不包含多用户服务或向量库。
